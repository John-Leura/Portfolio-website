    Steganography Tool

    Steganography · Summer 2025

    A team-built JPEG steganography tool that embeds files into JPEG images and extracts them using quantized DCT coefficients.

    Project overview

    The project report describes a C implementation with fixed least-significant-bit embedding and an adaptive mode. It discusses file embedding and extraction, JPEG processing, testing, and technical challenges.

    My contribution

    The report credits me as team leader/secondary coder. My work included JPEG reading and cleanup, message loading and bit extraction, testing and debugging, and the final report.

    Team 7: John Leura, Christian Evans, Christopher Perez, and Yousef Noor · CS 4463 · August 7, 2025.

    Choose how visitors explore the code

    These are design choices for the next step. Code and tool downloads will be added after a choice is made and the project files are uploaded.

    Option A — GitHub repository and downloads

    Show a project summary and buttons for Browse source on GitHub and Download tool. Visitors explore folders and code on GitHub; a packaged tool can be linked from a release.

    Best for: the simplest setup and maintaining one source repository.

    Tradeoff: browsing the files takes visitors away from the portfolio.

    Option B — File browser inside this page

    Add an expandable folder tree and a code viewer alongside it. Clicking a file displays its contents here. Provide individual file downloads and a Download project ZIP link; add a separate tool download when a packaged build is available.

    Best for: exploring folders, reading code, and downloading files without leaving the website.

    Tradeoff: the displayed files and download packages need updating when the project changes.

    Option C — In-page browser plus GitHub Recommended

    Combine Option B’s folder tree and code viewer with a link to the GitHub repository. Include separate downloads for the source ZIP and the packaged tool.

    Best for: your requested GitHub-style experience inside the portfolio, with the repository available for history and further exploration.

    Tradeoff: a little more setup; published downloads and the in-page files must stay in sync with the chosen code version.

    Option D — Run a version of the tool in the browser

    Add image and payload pickers so visitors can try embedding or extraction on the page. This would require reviewing and adapting the C code, potentially using WebAssembly, then testing the result.

    Best for: a future interactive demonstration after the source and downloads are ready.

    Tradeoff: substantially more development work. Uploading a Windows executable alone will not make it run inside a webpage.

    Choose A, B, or C for the initial code showcase. Option D can be a later addition. No file browser or tool download has been enabled yet.
